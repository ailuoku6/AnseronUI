# 本地性能验证快照

采样日期：2026-11-13。环境：Apple M5、darwin arm64、内核 27.2.0、Node v24.19.0。以下是本次实现的可复跑记录；不同机器的绝对耗时不能直接比较。

场景为 5000 行不同长度文本，5 次创建/销毁，每次 26 次深度滚动，去掉每轮 2 次预热后共 120 个更新样本，同时检查窄屏重排和隐藏/恢复。三个模式串行运行，采样期间没有并行编译。

| 模式 | 首屏中位数 ms | 更新中位数 ms | 更新 p95 ms | 挂载节点峰值 | 最大消息字节数 | 稳定测量缓存 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Reference JS | 10.23 | 8.78 | 13.49 | 78 | 126269 | 200 |
| Native AOT | 17.38 | 17.50 | 23.48 | 78 | 126255 | 200 |
| Wasm | 24.96 | 25.30 | 39.89 | 78 | 126255 | 200 |

以上使用真实 Core、合成 Renderer 和确定性文本测量；Native/Wasm 通过独立进程标准输入输出通信。首屏从显示已创建的隐藏页面开始，不包含加载二进制和启动进程。这些数字不代表实际平台帧率。Reference 另外用同机第一次报告验证了相对门槛：首屏中位数和更新 p95 不超过基线 1.3 倍加 2ms。

本次功能验证还包括：

- 共享框架 73 项测试、TypeScript 类型检查、工具链 27 项通过及 2 项平台条件跳过、构建脚本 7 项和 SDK 打包测试通过。
- Native/Wasm Core 原有页面协议回归通过；iOS、Android、Native 和 Wasm AOT 构建通过。
- Android API 35 模拟器 15 项测试通过，覆盖真实可变高度列表滚动、展开、定位和隐藏计时，以及保活回收。
- iOS 26.4 模拟器 19 项 UIKit 容器测试通过，覆盖可见性通知、内存警告和原参数重建。该测试集不包含 UIKit 5000 行列表滚动性能验证。
- AppKit 真实 AOT 集成通过，覆盖列表、媒体/动画、页面生命周期、容量限制和内存回收。
- WebKit Reference/Wasm 真实 DOM 列表流程通过，覆盖 20 次滚动、展开、深处定位、插入锚点、隐藏恢复和 resize。
- WebKit 路由回归通过，覆盖参数、输入/Hook 状态保留、返回、替换以及隐藏时屏蔽点击；此测试控制 `document.hidden` 通知，避免命令行宿主固定后台状态阻止交互。

iOS 27 模拟器要求 UIScene 生命周期，当前示例采用旧应用生命周期，测试宿主在启动阶段被系统拒绝；本次 UIKit 验证使用 iOS 26.4。WebKit 命令行宿主可能被后台调度限流，报告保留 `paintWaitTimeouts`；带 RAF 等待的交互时延不能作为纯计算时间。

完整本机 JSON 保存在忽略跟踪的 `.verification/performance/`。采样方法、指标定义和预算见[性能验证](../../docs/diagnostics/performance.md)。当前没有进程 RSS、GPU 时间或移动设备 FPS 的自动门槛；节点和缓存有界不能证明所有平台资源都没有泄漏。

## Android 猛烈甩动专项（2026-11-13，后续优化）

同一 API 35 模拟器，Debug APK、真实 AOT Core 和 Android View 树，5000 行可变高度列表。先等待深处定位完成，然后连续三轮 ±20000 px/s 惯性滚动，每次采样 2.5 秒；关闭 profiling 和逐帧诊断日志。每帧检查整个视口覆盖，并跟踪上一帧首个可见行是否反向移动。初始版本同场景曾出现向下最长 967ms、向上最长 1251ms 空白；早期跳动统计跟踪了所有行，与最终首可见行统计口径不同，不作数值比较。

| 次序 | 方向 | 采样帧数 | 空白帧数 | 最长空白 ms | 首可见行反向位移 px | 实际经过行数 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 向下 | 150 | 0 | 0 | 0 | 41.5 |
| 2 | 向上 | 150 | 0 | 0 | 0 | 39.9 |
| 3 | 向下 | 150 | 0 | 0 | 0 | 36.1 |
| 4 | 向上 | 149 | 0 | 0 | 0 | 41.7 |
| 5 | 向下 | 150 | 0 | 0 | 0 | 37.3 |
| 6 | 向上 | 146 | 0 | 0 | 0 | 38.8 |

最终共 895 帧未采到空白或反向跳动。此前独立的一轮六次甩动共 889 帧也未采到空白。回归门槛为连续空白≤150ms、空白帧≤10%、反向位移≤2px，并要求每次实际经过至少10行，防止靠停止滚动满足覆盖断言。这些结果只描述本机采样，不代表所有设备或无限复杂行内容的帧率承诺。

改动包含双向预热、按真实运动速度预测、稳定窗口、同批锚点补偿、编码前滚动合并、批量测量、提交去重复，以及有界文本/按钮复用。Android 在惯性接近已渲染区域边缘时平滑减小本帧位移，窗口补齐后正常推进；重负载下单次甩动距离可能变短，未消耗位移不会累积成跳跃。可见内容与预渲染目标最多32行（可见行自身更多时优先覆盖），原生离屏复用池另外最多64个文本和32个按钮，销毁时清空。

最终共享80项、Android RenderViewTest 16项、TypeScript检查通过；新增协议有限数校验、补偿不改变预测方向、父更新保持窗口、宿主事件屏障、原生锚点、控件复用状态/事件身份等回归。WebKit Reference 列表流程通过，最多32行，但后台绘制等待超时22次，不能把其约1秒交互p95视为计算耗时。iOS/macOS源码类型检查通过，本轮未重新跑这些平台的真实猛烈甩动，也未重建其应用产物。

扩大双向预热有计算与内存代价。最终Reference合成基准120样本：首屏中位12.70ms、更新中位17.87ms、更新p95 33.21ms，挂载节点峰值168、消息峰值291463字节、稳定测量缓存582，满足200节点/1024缓存/1MiB资源预算。此处没有声称通过旧版更小窗口的相对耗时门槛；Native/Wasm旧表仍为先前版本，未当作本轮结果。原始结果：`.verification/performance/fling-reference.json`、`android-fling.json`。
