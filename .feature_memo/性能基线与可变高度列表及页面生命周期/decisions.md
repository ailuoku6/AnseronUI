# Decisions

## 2026-11-13

- 使用真实测量 + 估算，支持未知行高；不要求业务预先计算所有高度。
- 滚动补偿放在提交后，防止原生旧 contentSize 把新 offset 截断。
- onLayout 由 Core 在 ACK 后统一派发，去掉各 Renderer 重复回放 SetFrame 的通知。
- 测量缓存提交后淘汰，布局期间不淘汰；否则深处滚动超过容量会破坏 3 轮收敛。
- 页面回收采用销毁后重新挂载，明确丢弃 Hook 状态；业务持久数据应放在外部模型。
- 默认无限保活以兼容既有行为；应用可显式限制总存活页数并接入内存压力。

## 验证与资源边界（2026-11-13）

- 合成 Renderer 吞吐基准与真实 UI 功能回归分开记录，累计阶段存在包含关系，不直接求和或换算 FPS。
- iOS27 拒绝旧 AppDelegate 宿主启动，使用 iOS26.4 做本次容器回归；UIScene 迁移不夹带进入本需求。
- 命令行 WebKit 会固定报告 document.hidden，即使窗口已展示；路由测试显式控制可见性通知，并验证隐藏点击被屏蔽。真实列表仍使用显式宿主可见性。
- 真实 WKWebView 每50ms无副作用调用保持可运行，RAF超时被记录，后台约1秒调度等待不能当计算耗时。

## 快速滚动修复

- 在Core合并过期滚动状态，减少跨端反复构造已离屏窗口，不用扩大overscan掩盖事件队列积压。
- 滚动偏移是原生视口当前状态，接受存活节点迟到的已提交版本；点击仍需原有版本校验和顺序。
- Android父View为阴影允许overflow，ScrollView必须在自身dispatchDraw明确裁剪；clipChildren只限制巨大content子视图不能提供所需viewport边界。
- 原先只检查存在的节点不能发现屏幕空白；新增原生全视口覆盖、最终偏移与像素裁剪回归。

## 2026-11-13 猛烈甩动优化

不能只增大overscan：速度必须扣掉布局补偿，且窗口要跨父组件更新保持稳定。Android在编码之前合并连续scroll，离散事件为屏障。回滑锚点以原生实际可见行优先，补偿与布局同批生效，保留惯性速度。性能回归必须关闭profiling，以首可见行反向位移衡量跳动。

- 最终补充：真实异步渲染无法仅靠预测覆盖任意速度：最终采用有界预热+原生余量保护。负载大时允许单次fling距离变短，保证视口内容连续；测试要求每次至少经过10行，不允许停住作弊。最终实际36–42行/次。
